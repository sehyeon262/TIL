## RESTful API
- REST는 **Representational State Transfer**의 약자로, 웹에서 자원을 다루는 아키텍처 스타일입니다.
- 핵심은 자원을 URL(고유 식별자)로 표현하고, 자원에 대한 행위는 HTTP 메서드로 정의한다는 점입니다.
- 예를 들어 GET은 조회, POST는 생성, PUT은 수정, DELETE는 삭제로 매핑됩니다.
- RESTful API는 클라이언트와 서버 간의 통신을 단순하고 일관성 있게 만들어줍니다
- 이 방식의 장점은 확장성, 가독성, 그리고 유지보수성이 뛰어나다는 것입니다.
- 또한 무상태(Stateless) 특성을 가져, 서버가 클라이언트 상태를 보관하지 않아 효율적입니다.
- JSON이나 XML 같은 포맷으로 데이터를 주고받을 수 있지만, 보통은 JSON을 많이 사용합니다.
- 대표적인 사례로는 Open API, SNS 로그인 연동, 금융권 데이터 조회 API 등이 있습니다.
- 다만, 모든 상황에서 RESTful이 완벽한 것은 아니며, 실시간성이 중요한 경우엔 WebSocket 같은 방식이 더 적합할 수 있습니다.

### 정리하면
- RESTful API는 자원을 직관적으로 표현하고, HTTP 규칙을 활용해 효율적으로 통신하는 표준화된 방법이라고 말할 수 있습니다

## SOLID 원칙
**SOLID 원칙은 객체지향 설계에서 유지보수성과 확장성을 높이는 다섯 가지 핵심 원칙입니다.**

1. **단일 책임 원칙(SRP)**
- 클래스가 하나의 책임만 가지도록 설계하는 원칙 
- 여러 기능이 섞여 있으면 수정 시 다른 기능에 영향을 줄 수 있으므로 이를 방지함

2. **개방-폐쇄 원칙(OCP)**
- 기존 코드를 변경하지 않고 새로운 기능을 추가할 수 있어야 한다는 원칙
- 기능 확장 시 안정성을 유지할 수 있음

3. **리스코프 치환 원칙(LSP)**
- 자식 클래스가 부모 클래스를 완전히 대체할 수 있어야 한다.
- 상속 구조에서 예측 가능한 동작을 보장

4. **인터페이스 분리 원칙(ISP)**
- 한 인터페이스가 너무 많은 기능을 담지 않고, 사용하는 클라이언트에 맞게 잘게 나누어져야 한다는 원칙
- 이렇게 하면 불필요한 의존성을 줄일 수 있음

5. **의존 역전 원칙(DIP)**
- 상위 모듈이 하위 구현체에 의존하지 않고, 추상화된 인터페이스에 의존해야 한다는 원칙
- 이를 통해 모듈 간 결합도를 낮추고 유연성을 확보할 수 있음

### 결론
- SOLID 원칙은 코드 수정 시 버그 가능성이 줄고 테스트가 쉬워지며, 협업 시 코드 구조가 명확해짐
- 따라서 실제 개발 과정에서 코드 품질을 높이는 실질적인 가이드라인이라 할 수 있음

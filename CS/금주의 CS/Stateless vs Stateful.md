# Stateless vs Stateful

## 1. 개념

### 🔹 Stateful (상태 유지)
- **Stateful**은 서버가 클라이언트의 상태를 **기억하는 방식**이다.
- 즉, 이전 요청의 정보를 서버가 저장하고 다음 요청에서도 활용한다.

---

### 🔹 Stateless (무상태)
- **Stateless**는 서버가 클라이언트의 상태를 **저장하지 않는 방식**이다.
- 즉, 각 요청은 **독립적이며 모든 정보를 포함**해야 한다.

---

## 2. 예시

### Stateful
```
로그인 → 서버가 사용자 상태 저장 → 이후 요청에서 상태 사용
```
예: Session 기반 인증

### Stateless
```
요청마다 토큰(JWT)을 포함 → 서버는 상태 저장 X
```
예: JWT 기반 인증

---

## 3. 차이 정리

| 구분 | Stateful | Stateless |
|---|---|---|
| 상태 저장 | 서버 | 없음 |
| 요청 관계 | 이전 요청 영향 있음 | 독립적 |
| 확장성 | 낮음 | 높음 |
| 서버 부담 | 큼 | 적음 |
| 예시 | Session | JWT |

---

## 4. 장단점

### Stateful

#### 장점
- 구현이 직관적
- 보안 관리 쉬움

#### 단점
- 서버 메모리 사용 증가
- 서버 확장 어려움 (Scale Out 불리)

---

### Stateless

#### 장점
- 서버 확장 용이
- 요청 처리 단순
- MSA에 적합

#### 단점
- 매 요청마다 데이터 포함 필요
- 보안 관리 어려움 (토큰 탈취 등)

---

## 5. 언제 사용하나

### Stateful
- 소규모 서비스
- 보안이 중요한 서비스 (금융 등)

---

### Stateless
- 대규모 서비스
- MSA 구조
- 확장성이 중요한 서비스

---

## 6. 핵심 포인트 (면접용)

- Stateful → 서버가 상태를 기억
- Stateless → 요청이 독립적
- JWT는 Stateless 인증 방식
- Session은 Stateful 인증 방식

---

## 7. 한 줄 정리

> Stateful은 서버가 상태를 저장하는 방식이고, Stateless는 상태를 저장하지 않고 요청마다 모든 정보를 포함하는 방식이다.

---

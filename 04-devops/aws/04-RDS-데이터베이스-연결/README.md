# 🗄️RDS로 데이터베이스 연결하기

EC2에 배포한 백엔드 서버가 사용할 데이터베이스를 AWS RDS에 생성하고 연결하는 과정을 정리한다.

- RDS 인스턴스 생성하기

- 파라미터 그룹 설정하기
- RDS에 접속하기
- Express와 Spring Boot 서버에 RDS 연결하기

## 먼저 알아야 할 핵심 개념

### 1) RDS란?

RDS(Relational Database Service)는 AWS에서 제공하는 관리형 관계형 데이터베이스 서비스다.

MySQL, MariaDB, PostgreSQL 같은 관계형 데이터베이스를 AWS 환경에서 생성하고 운영할 수 있다.

### 2) 왜 RDS를 사용할까?

로컬 환경에서는 내 컴퓨터에 설치한 MySQL 같은 데이터베이스를 사용한다.

하지만 백엔드 서버를 EC2에 배포하면, 데이터베이스도 EC2 서버가 접근할 수 있는 환경에 따로 구성해야 한다. 이때 AWS RDS를 사용하면 데이터베이스를 쉽게 생성하고 관리할 수 있다.

RDS는 데이터베이스 운영에 필요한 여러 기능을 제공한다.

- 자동 백업
- 모니터링
- 장애 대응
- 다중 AZ 구성
- 데이터베이스 엔진 업데이트 관리

### 3) EC2에 데이터베이스를 직접 설치하면 안 될까?

하나의 EC2에 백엔드 서버와 MySQL을 함께 설치할 수도 있다.

이 방식은 RDS 비용을 줄일 수 있어 개인 프로젝트나 학습 환경에서 사용할 수 있다. 하지만 EC2에 장애가 발생하면 백엔드 서버와 데이터베이스가 함께 영향을 받을 수 있다.

실제 서비스에서는 보통 백엔드 서버를 실행하는 EC2와 데이터베이스를 실행하는 RDS를 분리해서 구성한다.

### 4) EC2와 RDS의 연결

백엔드 서버는 RDS의 엔드포인트와 포트를 통해 데이터베이스에 연결한다.

이때 RDS는 외부에 공개하기보다, EC2에서만 접근할 수 있도록 보안 그룹을 설정하는 것이 일반적이다.

## 학습 후 할 수 있는 것

- RDS의 역할과 관리형 데이터베이스의 장점을 설명할 수 있다.
- RDS 인스턴스를 생성하고 데이터베이스에 접속할 수 있다.
- 보안 그룹을 이용해 EC2에서만 RDS에 접근하도록 설정할 수 있다.
- Express 또는 Spring Boot 서버에 RDS를 연결할 수 있다.
- 사용하지 않는 RDS 인스턴스와 스냅샷을 정리할 수 있다.

## 주의 사항

- RDS 인스턴스는 실행 중인 시간만큼 비용이 발생할 수 있다.
- RDS를 불필요하게 외부에 공개하지 않는다.
- 데이터베이스 비밀번호와 엔드포인트 정보는 GitHub에 올리지 않는다.
- RDS 삭제 시 남아 있는 스냅샷에도 비용이 발생할 수 있으므로 함께 확인한다.

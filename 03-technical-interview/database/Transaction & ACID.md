## Transaction & ACID

## Transaction (트랜잭션)
- **Transaction은 데이터베이스에서 하나의 작업 단위를 의미한다.**
- 즉, 여러 SQL 작업을 하나의 묶음으로 처리해서 모두 성공하거나 모두 실패하도록 보장한다.

### 예시
**계좌 이체 상황**
```
A 계좌 -1000
B 계좌 +1000
```

- A만 돈 빠지고
- B는 안 들어오면 안됨 (문제 발생)

=> 둘 다 성공하거나 둘 다 실패해야 한다

---

## ACID (트랜잭션의 4가지 특징)
1. **Atomicity (원자성)**
- 전부 실행되거나 전부 실패
- 일부만 실행 ❌

2. **Consistency (일관성)**
- 트랜잭션 전후 데이터가 일관된 상태 유지

3. **Isolation (격리성)**
- 동시에 실행되는 트랜잭션이 서로 영향 주지 않음

4. **Durability (지속성)**
- 성공한 데이터는 영구적으로 저장

---

### 왜 중요한가?
- 데이터 무결성 보장
- 금융 / 결제 시스템 필수
- 동시성 문제 해결


### 면접에서 이어지는 질문
- Isolation Level 종류 (Read Uncommitted ~ Serializable)
- Dirty Read / Phantom Read
- 트랜잭션이 느린 이유
- 낙관적 락 vs 비관적 락

### 한 줄 정리
- Transaction은 데이터 작업을 하나의 단위로 묶는 것이고, ACID는 그 안정성을 보장하는 4가지 특성이다.

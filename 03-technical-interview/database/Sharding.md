## Sharding (샤딩)

### 📌 개념
- Sharding은 데이터를 여러 데이터베이스 서버에 분산 저장하는 방법
- 즉, 하나의 DB에 모든 데이터를 넣는 게 아니라 **여러 DB로 나눠서 저장하는 것**

---

### 📌 왜 필요한가?
데이터가 많아지면
- DB 성능 저하
- 조회 속도 느림
- 서버 과부하
그래서
```
User Table -> 여러 DB로 분산
```
=> 부하 분산 + 성능 개선

---

### 📌 예시
예: 사용자 ID 기준 샤딩
```
1 ~ 1000   → DB1
1001 ~ 2000 → DB2
2001 ~ 3000 → DB3
```

---

### 📌 샤딩 방식
1. **Range Sharding**
  - 특정 범위 기준 분할 
    - 예: ID 1~1000
  - **단점**: 데이터 쏠림 발생 가능

2. **Hash Sharding**
  - 해시 함수 기반 분산
  - **장점**: 균등 분배
  - **단점**: 재분배 어려움

3. **Directory Sharding**
  - 별도 테이블로 위치 관리
  - 유연하지만 복잡함

---

### 📌 장점
- 데이터 분산 → 성능 향상
- 트래픽 분산
- 확장성 (Scale Out 가능)

---

### 📌 단점 (면접 핵심 ⭐)
- 조인 어려움
- 트랜잭션 처리 복잡
- 데이터 재분배 어려움

---

### 📌 Replication과 차이
| 구분  | Sharding | Replication |
| --- | -------- | ----------- |
| 목적  | 데이터 분산   | 데이터 복제      |
| 데이터 | 서로 다름    | 동일          |
| 목적  | 성능 향상    | 가용성         |

---

### 📌 한 줄 정리
> Sharding은 데이터를 여러 DB에 나눠 저장하여 성능과 확장성을 높이는 방식이다.

# 🔒ELB로 HTTPS 연결하기

EC2에 직접 요청을 보내던 구조에서 ELB를 앞단에 두고, 도메인에 HTTPS를 적용하는 과정을 정리한다.

## 이 섹션에서 배우는 것

- ELB가 무엇이고 왜 사용하는지 이해하기
- ELB의 기본 구성과 보안 그룹 설정하기
- 리스너, 라우팅, 헬스 체크 설정하기
- EC2에 연결된 도메인을 ELB에 연결하기
- ACM으로 SSL/TLS 인증서 발급하기
- ELB에 HTTPS 적용하기
- ELB 방식과 Nginx·Certbot 방식 비교하기
- 실습 후 비용이 발생하지 않도록 리소스 정리하기

## 먼저 알아야 할 핵심 개념

### 1) ELB란?

ELB(Elastic Load Balancer)는 사용자 요청을 여러 서버에 적절하게 분배해 주는 AWS 서비스다.

사용자가 EC2에 직접 요청하는 대신 ELB를 거치도록 구성할 수 있다. 서버가 여러 대일 때는 트래픽을 분산하고, 서버가 한 대여도 HTTPS 적용과 서버 상태 확인을 위해 사용할 수 있다.

### 2) SSL/TLS와 HTTPS란?

TLS는 클라이언트와 서버가 주고받는 데이터를 암호화하는 보안 프로토콜이다.

HTTPS는 HTTP 통신에 TLS를 적용한 방식이다. HTTPS를 사용하면 전송 중인 데이터를 보호할 수 있고, 사용자는 브라우저에서 안전한 연결인지 확인할 수 있다.

SSL은 이전 세대의 보안 프로토콜이며, 현재는 대부분 TLS를 사용한다. 다만 일상적으로는 SSL/TLS라는 표현을 함께 사용하기도 한다.

### 3) ELB 헬스 체크란?

헬스 체크는 ELB가 연결된 EC2 서버가 정상적으로 동작하는지 주기적으로 확인하는 기능이다.

ELB는 설정한 경로와 포트로 요청을 보낸다.

- 정상 응답을 받으면 `Healthy` 상태가 된다.
- 응답이 없거나 오류가 발생하면 `Unhealthy` 상태가 된다.
- `Unhealthy` 상태의 서버에는 트래픽을 보내지 않는다.

### 4) ELB를 적용한 구성

ELB를 적용하기 전에는 사용자가 EC2 서버의 IP 주소 또는 도메인으로 직접 요청을 보낸다.

ELB를 적용한 뒤에는 사용자가 ELB에 연결된 도메인으로 요청을 보내고, ELB가 EC2 서버로 요청을 전달한다.

이 과정에서 HTTPS는 ELB에 적용하고, ELB와 EC2 사이의 요청 전달 방식은 리스너와 대상 그룹 설정을 통해 관리한다.

- ELB 보안 그룹, 리스너, 대상 그룹을 설정할 수 있다.

## 주의 사항

- ELB는 생성한 동안 비용이 발생할 수 있으므로 실습 후 삭제한다.
- HTTPS 인증서를 발급하려면 도메인 소유 확인 절차가 필요하다.
- ELB 보안 그룹은 외부에서 들어오는 HTTP와 HTTPS 요청만 필요한 범위로 허용한다.
- EC2 보안 그룹은 모든 IP를 허용하기보다 ELB 보안 그룹의 요청만 허용하도록 설정한다.

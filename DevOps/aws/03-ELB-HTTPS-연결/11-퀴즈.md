# 🧩ELB와 HTTPS 퀴즈

ELB, 대상 그룹, ACM, HTTPS 설정 과정을 점검하는 퀴즈다.

문제를 먼저 풀어본 뒤 정답을 펼쳐서 확인한다.

## 1. ELB의 역할

ELB를 도입했을 때 사용자의 요청은 어디로 먼저 들어갈까?

<details>
<summary>정답 보기</summary>

ELB로 먼저 들어간다.

ELB는 요청을 받은 뒤 대상 그룹에 등록된 EC2 서버로 전달한다.

</details>

## 2. 대상 그룹

대상 그룹(Target Group)은 무엇을 의미할까?

<details>
<summary>정답 보기</summary>

ELB가 요청을 전달할 대상의 묶음이다.

이번 실습에서는 EC2 인스턴스를 대상 그룹에 등록한다.

</details>

## 3. 헬스 체크

헬스 체크가 필요한 이유는 무엇일까?

<details>
<summary>정답 보기</summary>

ELB가 EC2 서버의 정상 상태를 주기적으로 확인하기 위해서다.

정상 응답을 주지 못하는 EC2는 `unhealthy` 상태가 되고, ELB는 해당 서버로 사용자 요청을 전달하지 않는다.

</details>

## 4. 헬스 체크 경로

Express 서버의 헬스 체크 경로를 `/health`로 설정했다면, 서버는 어떤 응답을 반환해야 할까?

<details>
<summary>정답 보기</summary>

`GET /health` 요청에 성공 상태 코드인 `200`을 반환해야 한다.

</details>

## 5. 도메인 연결 대상

ELB를 도입한 뒤 Route 53 도메인은 무엇을 가리켜야 할까?

<details>
<summary>정답 보기</summary>

EC2의 탄력적 IP가 아니라 ELB를 가리켜야 한다.

Route 53에서는 ELB를 대상으로 하는 별칭 A 레코드를 사용한다.

</details>

## 6. HTTPS 인증서

ALB에 HTTPS를 적용할 때 인증서는 어느 AWS 서비스에서 발급받을까?

<details>
<summary>정답 보기</summary>

AWS Certificate Manager(ACM)에서 발급받는다.

인증서는 ALB와 같은 리전에서 발급해야 한다.

</details>

## 7. HTTPS 리스너

HTTPS 요청을 받는 ALB 리스너의 기본 포트 번호는 무엇일까?

<details>
<summary>정답 보기</summary>

`443`이다.

ALB의 HTTPS `443` 리스너에 ACM 인증서를 연결하고, 대상 그룹으로 요청을 전달한다.

</details>

## 8. HTTP 리디렉션

HTTP `80` 포트로 들어온 요청을 HTTPS로 강제하려면 리스너의 동작을 어떻게 설정해야 할까?

<details>
<summary>정답 보기</summary>

HTTP `80` 리스너의 기본 동작을 HTTPS `443`으로 리디렉션하도록 설정한다.

일반적으로 상태 코드는 `HTTP_301`을 사용한다.

</details>

## 9. 보안 그룹

외부 공개 ALB의 보안 그룹에는 보통 어떤 인바운드 규칙이 필요한가?

<details>
<summary>정답 보기</summary>

인터넷 사용자의 요청을 받을 수 있도록 아래 포트를 허용한다.

- HTTP `80`
- HTTPS `443`

EC2 보안 그룹은 인터넷 전체가 아니라 ELB 보안 그룹의 요청만 허용하는 방식이 더 안전하다.

</details>

## 10. HTTPS 적용 방식 선택

단일 EC2 개인 프로젝트에서 ALB 비용이 부담된다면 어떤 HTTPS 적용 방식을 고려할 수 있을까?

<details>
<summary>정답 보기</summary>

EC2에 Nginx와 Certbot을 설치하는 방식을 고려할 수 있다.

Nginx가 외부 요청을 받고 Express 서버로 전달하며, Certbot이 Let's Encrypt 인증서를 발급하고 갱신한다.

</details>

## 핵심 점검

- ELB → 대상 그룹 → EC2의 요청 흐름을 설명할 수 있는가?
- 헬스 체크가 `unhealthy` 서버를 제외하는 이유를 설명할 수 있는가?
- Route 53 도메인의 연결 대상을 EC2에서 ELB로 바꿔야 하는 이유를 아는가?
- ACM 인증서를 ALB HTTPS `443` 리스너에 연결하는 과정을 이해하는가?
- HTTP `80` 요청을 HTTPS `443`으로 리디렉션하는 이유를 아는가?

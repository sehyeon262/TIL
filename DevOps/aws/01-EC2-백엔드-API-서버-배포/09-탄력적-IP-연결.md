# 📍탄력적 IP 연결하기

EC2를 중지했다가 다시 시작해도 바뀌지 않는 고정 IP 주소를 설정하는 방법을 정리한다.

## 이 글에서 배우는 것

- 기본 퍼블릭 IP의 특징 이해하기
- 탄력적 IP가 필요한 이유 알아보기
- 탄력적 IP를 할당하고 EC2에 연결하기
- 사용하지 않는 탄력적 IP를 정리하는 이유 이해하기

## 기본 퍼블릭 IP의 문제점

EC2 인스턴스를 생성하면 퍼블릭 IPv4 주소가 자동으로 할당된다.

하지만 이 IP 주소는 임시 주소다. 인스턴스를 중지했다가 다시 시작하면 IP 주소가 변경될 수 있다.

```mermaid
flowchart LR
    Stop["EC2 중지"] --> Start["EC2 다시 시작"]
    Start --> ChangedIP["기본 퍼블릭 IP 변경 가능"]
```

IP 주소가 바뀌면 사용자가 접속하는 주소도 바뀌고, 도메인이나 외부 서비스의 설정도 다시 수정해야 한다.

## 탄력적 IP란?

탄력적 IP(Elastic IP)는 AWS 계정에 고정으로 할당하는 퍼블릭 IPv4 주소다.

탄력적 IP를 EC2 인스턴스에 연결하면 인스턴스를 중지했다가 다시 시작해도 같은 IP 주소를 사용할 수 있다.

| 구분 | 기본 퍼블릭 IP | 탄력적 IP |
| --- | --- | --- |
| 할당 방식 | 인스턴스 생성 시 자동 할당 | AWS 계정에 직접 할당 |
| 인스턴스 중지 후 시작 | 변경될 수 있음 | 연결 상태라면 유지됨 |
| 사용 목적 | 임시 접속 | 고정된 서버 주소 운영 |

## 탄력적 IP 할당하기

AWS 콘솔에서 다음 순서로 탄력적 IP를 만든다.

1. EC2 콘솔의 `탄력적 IP` 메뉴로 이동한다.
2. `탄력적 IP 주소 할당`을 선택한다.
3. `할당` 버튼을 누른다.

이제 AWS 계정에 새로운 탄력적 IP 주소가 생성된다.

## EC2 인스턴스에 연결하기

할당한 탄력적 IP를 EC2에 연결한다.

1. 생성한 탄력적 IP를 선택한다.
2. `작업` 메뉴에서 `탄력적 IP 주소 연결`을 선택한다.
3. 연결할 EC2 인스턴스를 선택한다.
4. `연결` 버튼을 누른다.

연결이 완료되면 EC2의 퍼블릭 IPv4 주소 대신 탄력적 IP 주소로 서버에 접속할 수 있다.

```text
http://<탄력적-IP-주소>
```

## 주의 사항

- 탄력적 IP는 사용하지 않는데 할당만 되어 있으면 비용이 발생할 수 있다.
- 실습을 마친 뒤 탄력적 IP가 필요 없다면 반드시 릴리스한다.
- 이후 Route 53에서 도메인을 연결할 때도 탄력적 IP를 연결 대상으로 사용할 수 있다.
